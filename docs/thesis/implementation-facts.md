## 架构与数据

用户端采用 uni-app Vue3 编译 H5 和微信小程序；管理端采用 Vue3、Element Plus。后端为 Spring Boot 2.7.3，三模块 `sky-common`、`sky-pojo`、`sky-server`，包名 `com.sky`。MyBatis 持久化到 MySQL，Redis 用于商品/套餐缓存及营业状态。服务器默认 8080，统一使用 Asia/Shanghai。

业务数据主线：user → address_book；category → dish；orders → order_detail；orders → order_stock；groupon → groupon_member → orders；pickup_point 关联订单与拼团。订单明细保存交易名称/价格快照。库存预留与首次取消回补同事务；订单和团购状态分别记录，不能把已成团等同于已付款。

JWT 管理员与用户使用不同 claim、不同配置密钥；请求体 userId 不代表身份。用户只能维护本人的地址和订单；管理端通过受保护路由履约与统计。`/api/**` 成功码 200，旧 `/user/**`、`/admin/**` 成功码 1，前端请求层适配。

普通下单由公共服务读取数据库价格及可售库存，使用 BigDecimal 计价；请求中的 amount、商品名、价格不是成交依据。clientRequestId 与请求摘要配合，唯一索引约束相同用户请求；库存条件更新防止超卖。自提支付后产生提货码，核销仅允许合法付款状态与已成功团购。模拟支付和模拟退款仅记录数据库状态，没有调用真实微信资金接口。

## 演示脚本

1. 按部署手册初始化隔离演示库，展示当前数据来自 MySQL。说明所有姓名、商品和账号是虚构演示数据。
2. 在管理端登录，展示商品、库存、上下架，再在用户端刷新查看变化。
3. 用户登录、维护默认地址、选择自提或配送；展示价格由后端确定。
4. 两名用户开团和参团，展示人数及订单关系；明确付款采用模拟支付。
5. 自提单付款后显示码，后台核销，再次核销被拒绝；配送单依次接单、配送、完成。
6. 展示本人历史订单和消费记录；切换另一用户不能查看他人订单。
7. 展示统计与固定样例：2000-01-01 完成 3 件演示苹果，每件 12.50，营业额 37.50；第二天为 0。演示当日数据与这段历史样例日期分开。
8. 展示自动验收真实结果和未验证项；不把 H5 截图称为微信真机截图。

截图应由实际运行页面采集，并记录候选提交、访问地址、日期与操作。当前素材文件不包含生成或伪造的产品截图。
