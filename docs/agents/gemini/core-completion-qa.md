# 用户端核心整合与验证记录

日期：2026-10-25。前端来源为本记录所在的 `feat/core-frontend` 提交及其后续整合提交，不能用截图代替最终发布版本的全量验收。

## 已实现

- 商品分类、搜索、详情、购物车与直接购买均使用实际 API；首页、商品详情、订单、支付、拼团页面移除本地样例与失败后假成功。
- 地址支持新增、编辑、删除及设置默认；H5 与小程序共用可编辑的省市区字段，不依赖 H5 不支持的区域选择器。
- 配送只传本人 `addressBookId`；自提只传真实 `pickupPointId` 与提货人姓名、手机号。`deliveryType=1` 配送，`2` 自提。
- 下单只传商品 ID、正整数数量与履约信息，金额由服务器计算。公开 `checkout()` 服务把 UUID 和购买意图先持久化，网络失败后沿用同一 UUID 重试，成功或意图变化后才更换。
- 团购发送 DTO 的 `number` 字段，使用 `/joinable/{dishId}` 与 `/mine`；提交必须收到真实 `orderId` 才进入支付，不把团 ID 当订单 ID。
- 订单列表、详情、取消、模拟支付、配送状态与自提码按实际响应展示。非自提订单不显示提货码。明确说明模拟支付与模拟退款。
- 优惠券、邀请奖励、秒杀、评价等范围外页面从注册路由移除。独立商家、自提点端仅保留未开放说明页。

## 构建和公开服务验证

使用官方 Node 22.14.0 / npm 10.9.2，运行锁定依赖安装：`front/` 的 `npm ci --no-audit --no-fund` 成功，安装 546 个包；管理后台安装 58 个包。包与构建产物未提交。

| 命令 | 结果 |
| --- | --- |
| `cd front && node --test tests/checkout.test.mjs` | 通过 1 项公开服务测试；验证网络失败重试 UUID 相同、Long ID 保持字符串、配送类型与数量正确、客户端伪造金额不进入请求 |
| `cd front && npm run build:h5` | 通过，`DONE Build complete` |
| `cd front && npm run build:mp-weixin` | 通过，`DONE Build complete` |
| `cd front-admin && npm run build` | 通过；有大包体提示，不影响产物生成 |

TDD 证据：先执行测试得到缺失 `services/checkout.mjs` 的明确失败，再实现公开服务后通过；随后将请求标识断言收紧为 UUID v4，旧实现出现精确断言失败，修正后通过。隔离的是 uni 网络和存储边界，没有 mock 自己的业务模块。

初次在依赖下载未完成时尝试构建曾出现缺失模块；依赖完整安装后的上述构建成功。受本机沙箱影响，便携 Node 的父目录 `lstat` 需要提升沙箱权限；实际通过的构建使用了该权限。
