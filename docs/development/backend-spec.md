# 毕设后端与集成开发规格

## Problem Statement

既有项目包含多端页面和部分后端实现，但接口、文档和技术栈不一致；示例数据和假成功掩盖错误，交易归属、计价、库存、团购与履约缺少完整验证，无法形成可信的毕设演示。

## Solution

在现有 Spring Boot 2.7 多模块后端上补齐真实交易闭环，冻结跨端契约，明确用户与管理员权限，按小业务任务实现并验证，再由独立验收者核对最终版本。

## User Stories

1. 作为开发者，我能按真实环境和配置构建后端，以便复现问题。
2. 作为用户，我看到真实商品和本人订单，不把示例数据当作交易。
3. 作为用户，我只能读取和修改本人的地址与订单。
4. 作为用户，我通过已认证身份设置密码，未登录请求被拒绝。
5. 作为用户，我按服务端商品价成交，客户端改价不能改变金额。
6. 作为用户，我在库存不足或数量非法时得到明确失败。
7. 作为用户，我重复下单或支付不会产生重复交易、扣库存或提货码。
8. 作为用户，我能开团和参团，超时未成团时库存和模拟资金状态一致。
9. 作为管理员，我能按合法状态完成接单、配送、自提核销。
10. 作为管理员，我查看可复算的真实销量、营业额与团购统计。
11. 作为前端负责人，我依据明确契约联调而不猜测字段或路由。
12. 作为验收者，我获得与确定提交对应的测试命令、结果和未验证项。

## Implementation Decisions

- 保留 Boot 2.7.3、MyBatis、MySQL、Redis 和一份核心业务服务。
- 用户 API、旧用户接口和管理员接口维持现有响应码兼容，前端在请求层适配。
- 用户后续授权 Codex 接手全部核心模块：用户端、管理端、后端、部署和验收；使用独立工作树分工，验收结果仍区分开发者自测与外部设备验证。
- 用户 JWT 与管理员 JWT 分开；身份来自验签后的 claim。本人订单查询与管理员查询显式分开。
- 订单、支付、核销与团购是独立状态维度；状态值兼容现有实体。
- 金额由服务端 BigDecimal 计算；库存、幂等、取消和到期处置使用事务与数据库条件约束。
- 现有数据只用增量迁移；初始化、种子与测试重置分开。
- 当前基线与角色、状态契约优先完成，再推进依赖其上的交易和团购任务。

## Testing Decisions

用户已确认 HTTP 与公开服务接口为 A06–A11 的测试边界。通过真实控制器、鉴权、服务与 MyBatis 测试业务结果，不 mock 自己的业务模块；只隔离数据库和外部支付网关。先观察精确失败，再修复并验证。

首批使用独立 H2 数据库；MySQL 特有约束、增量迁移、跨进程并发、Redis、跨端和微信真机另行验证，不据 H2 通过推断全部端到端通过。测试数据为固定虚构样例，无生产凭据。

## Out of Scope

真实微信支付和退款、真实短信、复杂营销、独立骑手、多商户结算、虚构独立验收材料。微信真机验证依赖可用设备与微信开发者工具，缺少证据时保留未验证状态。

## Further Notes

本规格来源为用户确认的四 Agent 方案，当前首批为 C1–C3 与后续交易任务的测试基础。首批 PR 不宣称整个项目已经完成；其余任务继续保留为依赖明确的 Issues。
